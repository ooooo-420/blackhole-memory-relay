# 設計提案（wuu 的審美規則和流程）

這份 skill 記的是這位使用者實際說過的話和實際發生過的返工。它不取代通用的設計規範（Impeccable、Taste Skill、frontend-design 這類）；那些管「一般怎樣算好」，這份管「這個人要什麼」。兩者衝突時聽這份；這份沒寫到的，照通用規範。

規則會隨使用者的新回饋增減。使用者推翻某一條時，直接改這個檔。

## 流程：先給看，再動手

動到構圖、配色、角色、版面的改動，照這個順序。跳步驟的幾次都重做了。

1. **先找參考和現成工具。** 上網找同類做得好的例子，學它為什麼好，不照搬。要用到工具（字體、圖示、模擬器）先查有沒有現成的。
2. **出 2–3 個方向的草圖。** 方向之間要真的不同（構圖、氣質不同），不是同一版換顏色。每個方向套在真實內容上，用真的文字和數字，不放假字。說出你推薦哪一個和理由，但讓使用者選。
3. **選定後出完整畫面。** 把所有主要狀態畫出來：正常、空的、出錯、最重要的那一刻（例如到號）。使用者會在這一步調大小、位置、刪字。
4. **使用者說可以，才改真的程式。** 使用者說「不用問我了」「照這版做」時，就一路做完，不再逐項確認。
5. **做完給截圖。** 截圖要來自真的程式，不是另畫的稿。說清楚這是電腦上截的，手機上的實際觀感還沒驗證。

小改動（調亮一點、刪一行字、使用者已經說清楚要怎麼改）不用走全程，直接改，改完給圖。

草圖做法：寫一個 HTML，用 `scripts/render.py` 截成 PNG 給使用者看。多個方案放在同一張圖上並排，每個標上 A／B／C 和一句話說明。

## 審美規則

### 文字

- **不要解釋性的小字。** 標題下的灰色副標、「往左滑可以刪除」這類操作說明、「示例資料」這類備註，使用者會一個個圈起來叫你刪。介面要靠長相讓人看懂，看不懂就改設計，不是加說明。
- 必要的資訊（上次回報時間、錯誤原因）可以留，但要短，而且只在需要時出現。
- 給中國大陸用戶用的東西寫簡體字。
- 文字要對齊。引號開頭的行要做標點懸掛，不然第二行看起來歪。

### 樣子

- **不要「AI 味」。** 使用者點名過的：方方正正的輸入框、方方正正的清單、純黑底、卡片套卡片、到處一樣的圓角灰框。
- 底色不用純黑或純白。暖一點的紙色、炭灰都可以。
- 強調色只用一個，另外最多一個「出事了／到了」的顏色。
- 彩色底上的小字要量對比度（至少 4.5），不夠就加深底色或加粗字。
- 圖形要有質感和層次。不要太平面。
- **過渡要連續。** 漸層不能有接縫，滑出來的東西不能從圓角後面硬露出一塊。接縫和突兀的銜接是大忌。
- 留白要有構圖。刪掉東西後留下的空位要重新安排，不能就空著。主體大致和畫面裡另一個重心同高。

### 重點和層次

- **要讓某樣東西最顯眼，不靠單純放大。** 用顏色、位置、動作（別的東西朝它靠）、它是唯一不同的那個。
- 區分幾個東西時，不要只換顏色，也不要平均撒在四個角。要有主次和構圖。
- 一個畫面只放最重要的一兩個數字，其他的收起來或變小。

### 狀態和控制

- **狀態用角色或動作表達，不用警告條和文字。** 電腦離線＝吉祥物睡覺；到號＝整張票變色、吉祥物跳起來。
- 開關這類控制不要像是「後來貼上去的」。能和畫面裡已有的東西合在一起就合在一起（點吉祥物＝開關監控）。
- 提示「這裡可以點」也用動作（靠近時有東西朝它偏過去），不寫字。

### 動效

- 每個畫面一個主要的動畫時刻，其他的都要安靜。不要到處呼吸、閃爍。
- 動畫要有因果：東西撕下來要有去處（落成票根），不是飛走消失。
- 可點的東西按下去要有回饋。
- 太複雜、容易看起來像故障的動畫不做，換一個簡單但乾淨的。使用者自己提的點子也要老實評估做不做得好。

### 吉祥物和插圖

- 手寫 SVG 畫角色有上限。第一版很可能被說醜，要準備重畫，並且老實說：真的不滿意時，建議使用者用 AI 繪圖或找插畫師出圖，你負責放進版面和做動效。
- 角色放的位置要有規則（例如永遠扒在最重要的那張卡上），不要漂在半空中。
- 角色大小先保守，使用者常覺得太大。

### 加東西之前

- **沒有好想法就不加。** 參考圖好看也不照搬進來。提新功能或新裝飾時，先說它解決什麼問題。
- 工具類的介面（瞄一眼就走）清楚優先，動效和變化少一點；展示類的頁面（作品集）可以開得高。

## 怎麼跟使用者說

- 一次給完所有選項和你的推薦，讓使用者回一個字母就能決定。
- 教操作步驟時一步一步來，一次只講一步。
- 使用者說某樣東西醜，不要辯解，直接重做並說明這次改了什麼。
- 你自己看出來的問題主動說，不要等使用者截圖來問。
